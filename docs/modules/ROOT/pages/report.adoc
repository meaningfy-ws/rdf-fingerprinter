= The Report

The report, `main.html`, is one static page. It has one section per profiled graph (the default
graph first, then each named graph) and, inside it, one collapsible section per class instantiated
in that graph. It is rendered from the analysis of the collected statistics; it sends no queries of
its own (xref:statistics.adoc[Statistics and Settings]).

Every IRI is shown as `prefix:local` (for example `skos:prefLabel`), from the namespace table the run
resolved (xref:representations.adoc#prefixes[Prefixes]); hover a name for its full IRI. The table of
contents on the left lists graphs, namespaces and classes; the search box keeps the classes and
property rows whose names or IRIs match; the switches hide whole namespaces. Classes of `rdf`,
`rdfs`, `owl` and `sh` are hidden by default (xref:representations.adoc#filters[Namespace filters]).

There is one switch per prefix of a shown class or a shown property, so a namespace that holds only
properties gets one too. Switching a namespace off hides its class sections and its property rows in
every class section. Search and switches combine: a class shown only because some of its rows match
the search needs one such row whose switch is on. A property without a prefix has no switch and is
never hidden by one. The counts of shown and hidden classes follow the search and the switches. The
switches only hide parts of the page; to leave a namespace out of the page and every other output,
use `--exclude-namespace`.

`fingerprint-gen-doc profile.json -o out/` writes the same page again from a saved profile.

[#namespaces]
== Namespaces

The namespace table lists each prefix with its namespace, where the prefix came from, and its uses:
the instances of its classes plus the subjects of its properties, over every class and graph. It is
grouped by source (user, packaged, prefix.cc, generated) and, in each group, the most used namespace
comes first. A namespace excluded by `--exclude-namespace` that holds a term keeps its row, its uses
(counted before the exclusion) and its place, and is marked `excluded`. When a pitfall finding names the ontology itself (for example
`https://ontology.brainframe.com/2016/04/brainframe` beside the vocabulary
`…/brainframe#`), that IRI gets no prefix and is shown whole.

== Taxonomy

The *Taxonomy* section draws, per graph, the class tree from declared and implied parents. Each node
links to its class and shows its instances with a bar against the graph's most popular class. A parent
that is not profiled in the graph is a grey node without a count; a class with several parents sits
under the first one and has a "see" link under the others.

== Per class

Classes are grouped by namespace prefix and, in a namespace, the class with the most instances
comes first. Each class shows its number of instances, its precision (`exact` or `first N of M`, see
xref:statistics.adoc#precision-modes[Precision modes]), how many of its properties are data and how
many are object properties (a `mixed` property counts in both), and its parents, declared or
implied. The table of contents shows the same counts beside each class, as `12 · 4 d, 2 o`.

The property table is grouped as *Own*, *Refined* and *Inherited*; in each group the property used by
the most instances comes first, then the more confident one.

== Columns

[cols="1,3"]
|===
| Column | Meaning

| Property | The property used by instances of the class.
| Subjects | How many observed instances use the property.
| Min | The fewest values an instance has; `0` when some instances do not use the property.
| Max | The most values one instance has.
| Avg | The average number of values per observed instance (instances without it count as 0).
| Kind | `datatype_property`, `object_property` or `mixed`.
| Distinct values | How many distinct objects appear with the property.
| Value types | Datatypes and classes of the values, most frequent first.
| Confidence | Share of observed instances having the property.
| Cardinality | The accepted label (`exactly_one`, `zero_or_one`, …); `present` for a property found only by the completeness check.
| Inheritance | `own`, `inherited` or `refined` relative to the parents.
| Language coverage | Share of literal values with a language tag.
|===

A value that could not be computed is shown as `—`.

== Collection

The *Collection* section lists every measurement that failed, and the settings used. A failed
measurement is missing from the tables above it. The *Caveats and pitfalls* section lists sampled
classes, subjects without a type, the namespaces hidden by default with their class counts, the
excluded namespaces (the note line of each graph, xref:representations.adoc#filters[Namespace filters]),
IRIs that could not be written and, after a scan, the pitfall findings (xref:pitfalls.adoc[Pitfalls]).
Neither the collection failures nor the pitfall findings are filtered: they still name excluded
terms. A graph whose classes were all hidden or excluded reads _Every class of this graph is in a
hidden or excluded namespace (see caveats)._ Only a graph with no typed instance reads _This graph
has no typed instances._

== Reading it

* *Min 1, Max 1, Cardinality `exactly_one`* — a mandatory, single-valued property.
* *Min 0* — the property is optional for this class.
* *Several value types* — the property mixes kinds of values; often a sign of inconsistent data.
* *first N of M* — the numbers describe a sample; treat max and distinct values as lower bounds.
