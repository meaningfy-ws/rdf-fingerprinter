= API Reference

The library has one entry point, `fingerprint_report`, in `fingerprint.service_layer.handlers`.

== fingerprint_report

[source,python]
----
from pathlib import Path
from fingerprint.adapters.prefixes import PrefixCcList
from fingerprint.domain.views import GeneratorOptions
from fingerprint.service_layer.handlers import fingerprint_report
from fingerprint.service_layer.settings import load_user_prefixes, resolve_settings

settings = resolve_settings(selected_graphs=["http://example.org/graph/a"], config={"depth": "properties"})
report, run = fingerprint_report(
    "https://my.endpoint/sparql",
    Path("report"),
    settings,
    formats=["shacl", "puml"],
    options=GeneratorOptions(exclude_namespaces=["skos"]),
    user_prefixes=load_user_prefixes("my-prefixes.json"),
    prefix_list=PrefixCcList(),          # None (the default): no prefix.cc lookup
)
print(report)  # report/main.html; run.failures lists what could not be measured
----

`exclude_namespaces=["skos"]` leaves out every `skos:` term of the report and the shapes and
diagrams: the `skos:` classes, properties such as `skos:prefLabel`, and `skos:` object classes. Up to
3.2 it hid the `skos:` classes only. Values are matched as prefixes, prefix globs or IRI stems
(xref:representations.adoc#filters[Namespace filters]).

[cols="2,2,4"]
|===
| Parameter | Type | Meaning

| `sparql_endpoint_url` | `str` | The SPARQL query endpoint.
| `output_location` | `str \| Path` | An existing folder; `NotADirectoryError` otherwise.
| `settings` | `Settings` | The collection settings; build them with `resolve_settings` (xref:statistics.adoc#settings[Settings]).
| `formats` | `Sequence[str]` | Representations to write after the report: `shacl`, `puml` (`doc` is the report itself).
| `options` | `GeneratorOptions \| None` | Namespace filters, module size, shapes namespace (xref:representations.adoc[Representations]).
| `template` | `str \| Path \| None` | A template package of your own for the report page (below).
| `user_prefixes` | `list[NamespacePrefix] \| None` | Your prefixes, over the packaged ones (xref:representations.adoc#prefixes[Prefixes]).
| `prefix_list` | `PrefixListSource \| None` | Where to look up unnamed namespaces; `PrefixCcList()` reads prefix.cc, `None` looks up nothing.
| `checks` | `list[PitfallCheck] \| None` | The pitfall checks when `settings.pitfall_scan` is on; `None` loads the packaged catalogue. Build your own with `fingerprint.adapters.pitfall_catalogue.load_catalogue(user_dir, skip)` (xref:pitfalls.adoc[]).
| `sparql` | `SparqlPort \| None` | Any SPARQL port, for example a fake in tests.
|===

It returns the path of `main.html` and the raw run. Every usage error — an invalid setting, an
unwritable shapes namespace, a module size below 1 — is a `UsageError` (a `ValueError`) raised before
any query; an endpoint unreachable at the start raises `EndpointUnreachable`. `profile.json`, with its
namespace table, is saved before anything is rendered.

The filters are applied once, to the analysed profile, by `generate_representations`, which
`fingerprint_report` and `generate_from_profile_file` call. A `Generator`
(`fingerprint.service_layer.generators`) built directly from analytics hides the classes of the
hidden and excluded namespaces only: it keeps their other terms and writes no `excluded namespaces`
note.

The steps are also available separately: `collect`, `resolve_namespaces`
(`fingerprint.service_layer.prefixes`), `save_profile` and `generate_representations`
(xref:representations.adoc#from-python[From Python]).

=== Migrating from 2.x

`generate_endpoint_fingerprint_report`, `generate_report_builder_config` and `render_report` were
removed in 3.0. Replace

[source,python]
----
generate_endpoint_fingerprint_report(url, folder, selected_graphs=graphs, additional_config={"collection": cfg})
----

with

[source,python]
----
fingerprint_report(url, folder, resolve_settings(selected_graphs=graphs, config=cfg))[0]
----

A custom report template now renders the page's view model instead of `conf.profile` (below).

== Custom templates

A template package holds a `config.json` and a `templates/` folder of
https://github.com/meaningfy-ws/eds4jinja2[eds4jinja2] Jinja templates:

----
my_template/
├── config.json
└── templates/
    └── main.html
----

[source,json]
----
{
  "template": "main.html",
  "conf": { "title": "My structural fingerprint" }
}
----

The template receives `view`, a `ProfileDocument` (`model/fingerprint_views.yaml`), with every value
already written as text and every IRI as a short name: `view.overview`, `view.namespaces`,
`view.graphs[*].classes[*].properties`, `view.collection`, `view.caveats`. `conf` holds your
constants. Start from the packaged package in `fingerprint_report_templates/fingerprint_report/`.

WARNING: Values in `view` come from the endpoint and are untrusted. The report page is rendered with
autoescape on, custom packages included.

== Logging

Modules log through `logging.getLogger(__name__)` (`fingerprint.service_layer.handlers`, ...)
and configure nothing; configure logging in your application.
