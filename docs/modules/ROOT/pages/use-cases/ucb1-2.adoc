= UC-B1.2: Fingerprint from an embedding application

*Use Case Level:* Blue (User-goal) +
*Primary Actor:* Requester (an embedding application) +
*Supporting Actors:* Public function (the 1.x call); Settings resolver; Collector; SPARQL client; Analyser; Template renderer; Profile store +
*Scope:* rdf-fingerprinter — library API

This Blue use case refines xref:use-cases/ucw1.adoc[UC-W1: Fingerprint an endpoint]. The
shared contract is stated there. This page states only how the library call realises it.

== Stakeholders and Interests

As UC-W1.

== Brief Description

The embedding application calls `fingerprint_report` with an endpoint, an output folder and the
settings built by `resolve_settings`, optionally formats, generator options, a template package, its
own prefixes and a prefix list source. The function returns the path of the report and the run.

== Preconditions

As UC-W1.

== Trigger

As UC-W1.

== Success Guarantee (Postconditions)

This Blue path adds only:

. The return value is the path of `main.html` and the run, whose `failures` list what could not be
  measured (xref:api-reference.adoc[API reference]).
. A template package renders the report page from the document view model instead of the packaged one.

== Minimal Guarantees (On Failure)

. Exceptions instead of exit codes: `NotADirectoryError` for a missing output folder; `UsageError`
  (a `ValueError`, from `fingerprint.service_layer.settings`) for an invalid setting;
  `EndpointUnreachable` (from `fingerprint.adapters.sparql`) when the endpoint is unreachable at the
  start. From 2.1 both are also importable from their layer's `exceptions` module.
. Any other exception propagates unchanged; there is no library counterpart to exit 4. Some of them
  (a validation error from the model, a non-numeric count) are also `ValueError` subclasses, so a
  caller that must tell usage errors apart catches `UsageError`, not `ValueError`.
. Importing the library has no logging side effects.

== Extensions

1a. Unknown key in the `config` given to `resolve_settings` — usage error naming the key.

== Special Requirements

* The 1.x function `generate_endpoint_fingerprint_report` was removed in 3.0 (readable-representations
  DEC-9); see xref:api-reference.adoc[API reference] for the migration.
