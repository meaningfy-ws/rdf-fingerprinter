## Assessment given (agent, same day), checked against the code and libraries

1. **Dicts.** Built in analytics (≈18 places: helpers hand dicts on, validated once in `analyse`),
   collection (≈24: raw dicts for the profile model) and the generator views (≈34). Fix: construct
   the generated model classes directly; a new LinkML schema for the representation views (+ enums
   for formats, severities); the eds4jinja2 config dict is the one boundary that remains, confined to
   the renderer adapter.
2. **`domain/generated/`.** Move the generated `profile.py` (and the JSON Schema) to `domain/`.
   Analytics: its *model* (`ProfileAnalytics`…) is generated from `model/fingerprint_analytics.yaml`
   into the same `profile.py`; its *logic* (`domain/analytics.py`) is hand-written.
3. **Exceptions / IRI as LinkML: no.** LinkML generates data classes; a Python exception must subclass
   `Exception`. Failure *data* is already modelled (`Failure`, query-kind enum). IRI rules are
   functions. Keep both as code.
4. **`rows_from_json`.** rdflib parses SPARQL JSON results into `ResultRow`s of `URIRef` / `Literal`
   (typed, `.toPython()`) / `BNode` — verified on a sample result.
5. **The SPARQLWrapper client** is our adapter around the library (timeout, retries with backoff,
   failure classification, `ask`). rdflib's `SPARQLConnector` does POST + timeout and returns an
   rdflib `Result` directly — verified in the installed rdflib 7.6.0.
6. **Settings.** The Meaningfy pattern (`project-setup/references/settings-pattern.md`; as in
   mapping-workbench and ted-sws): an `env_property` resolver in adapters, one typed config class in
   `fingerprint/__init__.py`; constants become environment variables with defaults.
7. **eds4jinja2.** Its own path is `ReportBuilder.make_document()` (and its `build_report` CLI): one
   template → `output/<template name>`, written unchecked. We bypassed it for per-graph file names and
   the Turtle check before writing. eds4jinja2 is Meaningfy's (`../eds4jinja2`, 2.0.0, own spine):
   extend it upstream.

## Re-shape log

- **2026-10-31, DEC-5 amended while planning.** The answer "rdflib `SPARQLConnector`" rested on the
  assessment's claim that the connector does POST + timeout. Checked in rdflib 7.6.0 by the agent and
  by the clarity-gate reviewer: `SPARQLConnector.query` calls `urlopen(Request(...))` with no timeout
  argument, and on POST returns `(code, str, None)` when the endpoint answers with an HTTP error. The
  per-query timeout is a 2.0 requirement, so the query goes through `urlopen(..., timeout=...)` and
  rdflib's `Result.parse` reads the answer. SPARQLWrapper still goes; rdflib still provides the typed
  results. Awaiting the developer's confirmation.
